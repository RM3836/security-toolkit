## 一、项目概述

主动诱捕攻击者的安全防御系统。包含 **SSH 蜜罐**（伪造服务器记录攻击者行为）、**HTTP 蜜罐**（伪造登录页窃取攻击者输入）、**威胁情报**（IP 地理定位）、**实时仪表盘**（WebSocket 攻击流推送）四大组件。

## 三、四大组件详解

### 3.1 SSH 蜜罐 (ssh_trap.py)

**原理：** 用 Paramiko 库构建一个假的 SSH 服务器，伪装成 Ubuntu OpenSSH 8.9，接受任何密码登录，并提供一个完整的假文件系统。

#### 3.1.1 SSH 伪装技术

```
真实 SSH 交互流程：
  客户端 → TCP 连接 → 服务端 Banner: SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.1
  客户端 → 密钥交换 → 认证
  客户端 → 输入密码 → 服务端验证
  客户端 → 打开 Shell → 执行命令

蜜罐的伪装：
  服务端 Banner: SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.1  ← 伪造
  密码验证: 任意密码都通过                                   ← 记录密码
  Shell: 模拟 bash 环境，返回预设的假输出                     ← 记录命令
```

#### 3.1.2 伪造文件系统

```
蜜罐内嵌了一个完整的假 Linux 文件系统：

/
├── etc/
│   ├── passwd        ← 假用户列表（root, www-data, mysql, admin）
│   ├── shadow        ← 假密码哈希（诱饵）
│   ├── nginx/
│   │   └── nginx.conf ← 假 Nginx 配置
│   └── crontab       ← 假定时任务（含诱饵密码）
├── root/
│   ├── .bash_history ← 假命令历史（含 "mysql -u root -p'S3cur3P@ss!'"）
│   └── .ssh/
│       └── id_rsa    ← 假 SSH 私钥（"[REDACTED - KEY REMOVED]"）
├── var/www/html/
│   └── config.php    ← 假数据库配置（db_pass='W3bApp@2026!'）
└── opt/
    └── backup.sh     ← 假备份脚本（含 mysqldump 密码）
```

> **教学意义：** 这些假文件是精心设计的"诱饵"。攻击者看到 `.bash_history` 里的 MySQL 密码会尝试使用，从而暴露自己的行为。

#### 3.1.3 支持的命令

```bash
# 蜜罐支持 20+ 个常用命令的假输出：
whoami          → root
id              → uid=0(root) gid=0(root) groups=0(root)
hostname        → prod-server-01
uname -a        → Linux prod-server-01 5.15.0-58-generic ...
ps aux          → 假进程列表（nginx, mysql, sshd, cron...）
netstat -tlnp   → 假网络连接（22, 80, 3306, 6379...）
docker ps       → 假容器列表（mysql, redis, nginx...）
cat /etc/passwd → 假用户文件
ls              → 当前目录列表
cd <dir>        → 切换目录
cat <file>      → 读取文件内容
```

### 3.2 HTTP 蜜罐 (http_trap.py)

**原理：** 用 Flask 搭建伪装的 Web 服务，模拟常见的高价值攻击目标。

#### 3.2.1 伪装的登录页面

```
攻击者扫描到 8080 端口后，会尝试访问：

/wp-login.php  → WordPress 登录页面
  ├── 仿真的登录表单（Logo、样式、表单字段）
  ├── POST 提交的账号密码被完整记录
  └── 登录后显示"密码错误"（永远失败）

/phpmyadmin/   → phpMyAdmin 登录页面
  ├── 仿真界面
  └── 同样记录所有输入

/admin/        → 通用后台管理页面
```

#### 3.2.2 敏感文件陷阱

```
攻击者常用扫描器探测的敏感文件，蜜罐都返回假数据：

/.env 返回：
  DB_HOST=localhost
  DB_DATABASE=production_db
  DB_USERNAME=root
  DB_PASSWORD=W3bApp@2026!
  REDIS_PASSWORD=R3d!sS3cur3
  MAIL_PASSWORD=Gm@ilAppP@ss2026
  JWT_SECRET=xK9mN2pQ7rS4tU6vW8yZ0aB3cD5eF7gH...

/.git/HEAD 返回：
  ref: refs/heads/main

/.git/config 返回：
  [core]
  repositoryformatversion = 0
  [remote "origin"]
  url = https://github.com/fake-company/webapp.git
```

> **教学意义：** 攻击者拿到这些"凭据"后会尝试连接数据库，这个行为会被记录下来，暴露攻击者的 IP 和意图。

#### 3.2.3 全量请求记录

```
HTTP 蜜罐记录的信息：
├── 源 IP 地址
├── 请求方法（GET/POST/PUT/DELETE...）
├── 请求路径（URL）
├── User-Agent（浏览器/扫描器指纹）
├── POST 数据（表单提交内容）
├── 所有请求头部（完整记录）
└── 时间戳
```

## 四、⚡ 安全性教学重点

### 4.1 蜜罐中的假凭证设计（核心考点）

#### 设计原则：诱饵要逼真

```
❌ 不好的诱饵设计：
  DB_PASSWORD=123456       ← 太假，攻击者不会信

✅ 好的诱饵设计：
  DB_PASSWORD=W3bApp@2026!  ← 看起来像真实密码策略
  JWT_SECRET=xK9mN2pQ7rS4tU6vW8yZ...  ← 长度和格式都像真的
```

#### 本项目的假凭证清单

```
所有假凭证（均为蜜罐诱饵，不是真实密码）：

HTTP 蜜罐 .env 文件：
  DB_PASSWORD=W3bApp@2026!
  REDIS_PASSWORD=R3d!sS3cur3
  MAIL_PASSWORD=Gm@ilAppP@ss2026
  JWT_SECRET=xK9mN2pQ7rS4tU6vW8yZ0aB3cD5eF7gH1iJ4kL6mN9oP2qR=
  APP_KEY=base64:Kx7vN2mP8qR3sT5uW6yZ0aB1cD4eF7gH9iJ2kL5mN8oP1qR=

SSH 蜜罐 .bash_history：
  mysql -u root -p'S3cur3P@ss!'

SSH 蜜罐 config.php：
  db_pass = 'W3bApp@2026!'

SSH 蜜罐 backup.sh：
  mysqldump -u root -p'W3bApp@2026!' production_db

⚠️ 教学要点：
这些密码看起来像真实密码，但实际上只存在于蜜罐中。
攻击者拿到后会尝试连接真实数据库 → 连接失败 → 暴露自己的 IP 和意图。
```

### 4.2 蜜罐的安全隔离

```
⚠️ 蜜罐部署的安全要求：

1. 网络隔离
   ├── 蜜罐必须部署在独立的网络段
   ├── 蜜罐不能访问真实的生产系统
   └── 使用 VLAN / 防火墙规则隔离

2. 数据隔离
   ├── 蜜罐的 SQLite 数据库是独立的 (honeypot.db)
   ├── 假凭证不能与真实系统密码相同
   └── 日志不与生产日志混合

3. 监控与告警
   ├── 蜜罐被"攻破"时应触发告警
   ├── 定期检查蜜罐日志
   └── 蜜罐本身也需要更新和补丁

4. 法律合规
   ├── 蜜罐记录的攻击者数据属于个人信息
   ├── 数据保留期限需要符合法规
   └── 不得利用蜜罐主动攻击他人
```

## 五、代码架构教学

### 5.1 回调模式（Callback Pattern）

```python
# honeypot.py 中的中央事件总线

def attack_callback(event_type, data):
    """
    所有蜜罐组件都通过这个回调函数报告攻击事件
    实现了组件之间的解耦
    """
    # 1. 彩色终端输出
    print_colored_event(event_type, data)

    # 2. 存入数据库
    db.save_event(event_type, data)

    # 3. 推送到 WebSocket
    socketio.emit('new_attack', data)

    # 4. 加入内存事件队列
    events.append(data)

# SSH 蜜罐调用：
attack_callback('ssh_login', {'ip': '1.2.3.4', 'user': 'root', 'pass': '123456'})

# HTTP 蜜罐调用：
attack_callback('http_login', {'ip': '1.2.3.4', 'path': '/wp-login.php', 'user': 'admin'})
```

> **教学意义：** 回调模式让 SSH 蜜罐和 HTTP 蜜罐互不知道对方的存在，它们只需要调用 `attack_callback()` 就能触发所有下游处理。这是"观察者模式"的简化版。

### 5.2 多线程服务架构

```
honeypot.py 启动 4 个守护线程：

主线程
├── Flask-SocketIO 仪表盘 (port 5000)
│
├── 守护线程 1: SSH 蜜罐服务器 (port 2222)
│   └── Paramiko ServerInterface 处理每个连接
│
├── 守护线程 2: HTTP 蜜罐服务器 (port 8080)
│   └── Flask app 处理每个请求
│
├── 守护线程 3: 威胁情报富化
│   └── 每 5 分钟查询 ip-api.com 更新攻击者画像
│
└── 守护线程 4: WebSocket 事件推送
    └── 从内存队列读取事件，推送到浏览器
```

```python

    if attack_count <= 5:
        return 'LOW'        # 偶尔尝试
    elif attack_count <= 10:
        return 'MEDIUM'     # 持续尝试
    elif attack_count <= 20:
```

## 七、常见问题

| 问题 | 解决方案 |
|------|---------|
| `ModuleNotFoundError: paramiko` | `pip install paramiko` |
| SSH 蜜罐连接后立即断开 | 检查 Paramiko HostKey 是否正确生成 |
| HTTP 蜜罐页面样式丢失 | 内联 CSS，不需要外部文件，检查模板渲染 |
| 仪表盘没有实时数据 | 确保 WebSocket 连接正常（浏览器控制台检查） |
| ip-api.com 返回空 | 免费 API 有速率限制，等待 1 分钟后重试 |
| 端口被占用 | `lsof -i :2222` 检查谁在用，换端口或 kill 进程 |
| Windows 上无法绑定 22 端口 | 需要管理员权限，且 Windows 自带 SSH 服务可能占用 |
