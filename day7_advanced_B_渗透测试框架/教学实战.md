## 一、项目概述

AutoPen 是一个**自动化渗透测试框架**，集成信息收集、端口扫描、漏洞检测、安全利用、报告生成五大模块，通过 CLI 命令行驱动，模拟真实渗透测试全流程。

### 架构总览

```
用户输入目标
    │
    ▼
┌─────────────────────────────────────────┐
│           pentest.py（主控调度器）         │
│         argparse 解析参数 + 阶段调度       │
└───┬──────┬──────┬──────┬──────┬─────────┘
    │      │      │      │      │
    ▼      ▼      ▼      ▼      ▼
 Recon  Scanner  Vuln  Exploiter Reporter
 信息收集 端口扫描 漏洞检测 安全利用  报告生成
    │      │      │      │      │
    └──────┴──────┴──────┴──────┘
              结果聚合
                 │
                 ▼
         reports/ 目录
      (Markdown + JSON)
```

### 3.1 模块一：信息收集 (Recon)

**功能：** 在不与目标深度交互的情况下，收集尽可能多的公开信息。

```
信息收集流程：
│
├── 1. DNS 记录查询
│   ├── A 记录 → IP 地址（socket.getaddrinfo）
│   ├── MX 记录 → 邮件服务器（dig MX / nslookup）
│   ├── NS 记录 → 域名服务器
│   ├── TXT 记录 → SPF/DKIM/验证记录
│   └── CNAME 记录 → 别名记录
│
├── 2. HTTP 头部分析
│   ├── Server 头部 → 服务器类型（Nginx/Apache/IIS）
│   ├── X-Powered-By → 后端技术（PHP/ASP.NET）
│   ├── 响应体关键词 → 框架识别（WordPress/Django/React/Vue）
│   └── 安全头部检查 → 7 项安全配置
│
├── 3. 子域名枚举（多线程 DNS 爆破）
│   ├── 字典：wordlists/subdomains.txt（291 个常见前缀）
│   ├── 20 个线程并发查询
│   └── 输出：发现的子域名 + 对应 IP
│
└── 4. 敏感文件探测
    ├── /.env              ← 数据库密码、API Key
    ├── /.git/HEAD         ← Git 仓库泄露
    ├── /robots.txt        ← 爬虫规则（含隐藏路径）
    ├── /sitemap.xml       ← 网站地图
    ├── /phpinfo.php       ← PHP 配置信息泄露
    ├── /.htaccess         ← Apache 配置
    └── ... 共 13 个路径
```

**教学重点 — 子域名枚举原理：**
```python
# DNS 爆破：逐个尝试前缀 + 目标域名
# 例如目标是 example.com，尝试：
#   admin.example.com → DNS 查询 → 有 IP？发现子域名！
#   mail.example.com  → DNS 查询 → 有 IP？发现子域名！
#   test.example.com  → DNS 查询 → NXDOMAIN？不存在

# 使用 ThreadPoolExecutor 并发查询（20 线程）
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=20) as executor:
    futures = {executor.submit(resolve, sub): sub for sub in wordlist}
    for future in as_completed(futures):
        ip = future.result()
        if ip:
            print(f"[+] {sub}.{target} -> {ip}")
```

### 3.2 模块二：端口扫描 (Scanner)

**功能：** 发现目标开放的端口和运行的服务。

```
端口扫描流程：
│
├── 1. TCP Connect 扫描
│   ├── 扫描 68 个常见端口（20-27017）
│   ├── 100 个线程并发（ThreadPoolExecutor）
│   ├── socket.connect_ex() 返回 0 = 端口开放
│   └── 实时进度报告
│
├── 2. Banner 抓取
│   ├── HTTP 端口(80/443/8080等) → 发送 HEAD 请求
│   ├── SMTP(25)/FTP(21) → 发送 CRLF 获取 Banner
│   ├── SSH(22) → 被动读取服务器 Banner
│   └── 其他端口 → 尝试读取欢迎信息
│
└── 3. OS 指纹识别
    ├── 运行 ping 获取 TTL 值
    ├── TTL <= 64  → Linux
    ├── TTL <= 128 → Windows
    ├── TTL <= 255 → Solaris/网络设备
    └── 端口特征辅助判断
        ├── 3389 + 445 开放 → Windows
        └── 仅 22 开放 → Linux
```

**教学重点 — TCP Connect 扫描原理：**
```python
import socket

def scan_port(host, port, timeout=1.0):
    """
    TCP Connect 扫描原理：
    1. 调用 connect_ex() 尝试三次握手
    2. 返回 0 → 连接成功 → 端口开放
    3. 返回非 0 → 连接失败 → 端口关闭/被过滤
    """
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(timeout)
    result = sock.connect_ex((host, port))
    sock.close()
    return result == 0
```

**教学重点 — OS 指纹原理：**
```python
# TTL（Time To Live）是 IP 头部的生存时间字段
# 不同操作系统的默认 TTL 不同：
#   Linux:    64
#   Windows:  128
#   Solaris:  255
# 
# 方法：ping 目标，读取响应的 TTL 值，反推操作系统
# 注意：TTL 会随路由跳数递减，所以用 <= 判断
```

### 3.3 模块三：漏洞检测 (Vuln)

**功能：** 自动化检测目标的常见安全漏洞。

```
漏洞检测流程：
│
├── 1. SQL 注入检测
│   ├── 错误型注入：发送特殊字符，检查响应中的 SQL 错误信息
│   │   Payload: '  "  1=1  ' OR '1'='1  UNION SELECT
│   │   检测: mysql_fetch  SQL syntax  ORA-  PostgreSQL
│   │
│   └── 时间型注入：发送延时函数，测量响应时间差
│       Payload: ' OR SLEEP(5)--  '; WAITFOR DELAY '0:0:5'
│       检测: 响应时间 > 4 秒
│
├── 2. XSS（跨站脚本）检测
│   ├── 反射型 XSS：在参数中注入脚本，检查是否原样输出
│   │   Payload: <script>alert(1)</script>
│   │            <img src=x onerror=alert(1)>
│   │            <svg onload=alert(1)>
│   │   检测: payload 是否出现在响应正文中
│   └── 测试参数: q, search, query, keyword, name, page
│
├── 3. 目录遍历检测
│   ├── Payload: ../../../etc/passwd
│   │           ..\..\..\windows\win.ini
│   │           %2e%2e%2f (URL编码)
│   └── 检测: 响应中是否包含 root:/bin/bash 或 [extensions]
│
├── 4. 命令注入检测
│   ├── Payload: ;id  |id  `id`  $(id)
│   ├── 测试参数: cmd, exec, command, ping, host
│   └── 检测: 响应中是否包含 uid=/gid=
│
└── 5. SSL/TLS 安全检查
    ├── 连接 443 端口，提取证书信息
    │   ├── 主体（Subject）和颁发者（Issuer）
    │   ├── 有效期（Not Before / Not After）
    │   └── SAN（Subject Alternative Names）
    ├── TLS 版本检查：TLSv1.0/1.1 标记为弱版本
    └── 弱密码套件检测：RC4, DES, 3DES, MD5, NULL
```

**教学重点 — SQL 注入检测原理：**
```python
# 错误型注入：利用数据库报错信息判断漏洞
# 正常请求: GET /page?id=1        → 200 OK
# 注入请求: GET /page?id=1'       → 500 + "You have an error in your SQL syntax"
# 结论: 参数 id 直接拼接到 SQL 语句，存在注入

# 时间型注入：利用延时函数判断漏洞
# 正常请求: GET /page?id=1        → 响应 0.2s
# 注入请求: GET /page?id=1' OR SLEEP(5)--  → 响应 5.2s
# 结论: SQL 语句被执行，存在盲注
```

### 3.4 模块四：安全利用 (Exploiter)

**功能：** 在发现漏洞后，进行安全的、只读的利用验证。

```
安全利用流程（所有操作均为只读/伦理性质）：
│
├── 1. 默认凭据测试
│   ├── 5 组常见账号密码（admin/admin, root/root 等）
│   ├── 5 个常见登录路径（/login, /wp-login.php 等）
│   └── 检查登录是否成功（非 200 且无 "error" 关键词）
│
├── 2. SSH 安全检查
│   ├── 读取 SSH Banner（版本信息）
│   ├── 检查是否为 SSHv1（已淘汰，存在安全问题）
│   └── 检查 OpenSSH 版本（< 7.0 标记为过时）
│
├── 3. 目录列表检测
│   ├── 探测 20 个常见目录（/images/, /uploads/, /backup/ 等）
│   └── 检查响应中是否包含 "Index of" 或 "Directory listing"
│
└── 4. 信息泄露收集
    ├── 版本头部信息（Server, X-Powered-By）
    ├── HTML 注释中的敏感关键词（password, secret, key, token）
    ├── 邮箱地址收集（正则匹配）
    ├── 内网 IP 收集（RFC1918 地址段匹配）
    └── 敏感路径探测（/admin, /.env, /swagger, /graphql 等）
```

**教学重点 — 伦理边界：**
```
✅ 可以做的（只读/信息收集）：
├── 检查默认密码是否能登录（不修改任何数据）
├── 读取 SSH Banner 版本
├── 检查目录列表是否开启
└── 收集公开可访问的敏感文件

❌ 绝对不能做的：
├── 修改/删除数据库数据
├── 上传 WebShell
├── 提权操作
├── 内网横向移动
└── 任何造成服务中断的操作
```

### 4.3 安全工具开发的编码规范

```python
# 1. 输入验证 — 防止工具本身被利用
def clean_target(target):
    """清理目标地址，防止注入"""
    target = target.strip()
    target = target.replace('http://', '').replace('https://', '')
    target = target.rstrip('/')
    if ':' in target:
        target = target.split(':')[0]
    return target

# 2. 超时控制 — 防止线程泄漏
sock.settimeout(timeout)  # 每个连接都设超时

# 3. 异常捕获 — 防止单点故障导致整个工具崩溃
try:
    result = dangerous_operation()
except Exception as e:
    print(f"[!] 操作失败: {e}")
    return default_value

# 4. KeyboardInterrupt 处理 — Ctrl+C 也能保存报告
try:
    run_all_phases()
except KeyboardInterrupt:
    print("\n[!] 用户中断，生成部分报告...")
```

## 五、代码架构教学

### 5.1 管道模式（Pipeline Pattern）

```
pentest.py 的调度逻辑：

recon_result = ReconModule(target).run()       # 阶段1
    │
    ▼
scan_result = ScannerModule(target).run()      # 阶段2
    │
    ▼
vuln_result = VulnModule(target).run()         # 阶段3
    │
    ▼
exploit_result = ExploiterModule(target).run() # 阶段4
    │
    ▼
ReporterModule(target, all_results).run()      # 阶段5

每个阶段的输出 = 下一阶段的输入
全部结果汇总到 Reporter 生成报告
```

### 5.2 模块化设计

```
每个模块都是独立的类，遵循统一接口：

class SomeModule:
    def __init__(self, target, **kwargs):
        self.target = clean_target(target)
        self.results = {}

    def run(self) -> dict:
        """执行模块逻辑，返回结果字典"""
        ...
        return self.results

这种设计的好处：
├── 可以独立测试每个模块
├── 可以自由组合阶段（--phase recon,scan）
├── 新增模块只需实现 .run() 方法
└── 模块之间松耦合，互不依赖
```

### 5.3 多线程扫描模式

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=100) as executor:
    # 提交所有任务
    futures = {
        executor.submit(scan_one_port, port): port
        for port in port_list
    }

    # 按完成顺序处理结果
    for future in as_completed(futures):
        port = futures[future]
        try:
            is_open = future.result()
            if is_open:
                print(f"[+] {port}/tcp 开放")
        except Exception as e:
            print(f"[!] {port} 扫描异常: {e}")
```

> **教学意义：** `as_completed()` 让我们按完成顺序处理结果，而不是按提交顺序。这在端口扫描中很重要 — 快速响应的端口先出结果，不用等慢的。

## 七、常见问题

| 问题 | 解决方案 |
|------|---------|
| `Permission denied` 扫描端口 | 普通用户可以做 TCP Connect 扫描，不需要 root |
| 子域名枚举全部失败 | 检查 DNS 是否正常：`dig example.com` |
| 漏洞检测全部跳过 | 目标可能没有可测试的 Web 应用，换 `testphp.vulnweb.com` |
| SSL 检查报错 | 目标 443 端口可能未开放，或使用了自签名证书 |
| 报告为空 | 确保前面的阶段有发现，`--phase all` 跑全流程 |
| KeyboardInterrupt 后没有报告 | 框架会尝试生成部分报告，检查 `reports/` 目录 |
