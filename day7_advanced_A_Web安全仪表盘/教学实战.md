## 一、项目概述

基于 Flask + SocketIO 的**实时安全监控面板**，集成端口扫描、Web 漏洞扫描、日志分析三大功能模块，通过 WebSocket 实时推送告警。

### 技术架构

```
┌─────────────────────────────────────────────┐
│              浏览器 (Bootstrap 5 Dark)        │
│         Chart.js 趋势图 + Socket.IO 客户端    │
└──────────────┬──────────────────────────────┘
               │ HTTP + WebSocket
┌──────────────▼──────────────────────────────┐
│          Flask + Flask-SocketIO              │
│  ┌──────────┬──────────┬──────────────────┐ │
│  │ 端口扫描  │ Web扫描   │ 日志分析         │ │
│  │(socket)  │(requests) │(正则解析auth.log) │ │
│  └──────────┴──────────┴──────────────────┘ │
│              SQLite 持久化存储               │
└─────────────────────────────────────────────┘
```

### 核心文件说明

| 文件 | 作用 | 代码行数 |
|------|------|---------|

## 三、功能实战演示

### 3.1 端口扫描

**操作步骤：**
1. 登录后进入仪表盘，点击顶部导航栏"扫描中心"
2. 选择"端口扫描"标签页
3. 输入目标地址（如 `scanme.nmap.org` 或 `127.0.0.1`）
4. 点击"开始扫描"

**技术原理：**
```
扫描流程：
1. TCP Connect 扫描 — 用 socket.connect_ex() 尝试连接
2. 多线程并发 — 100 个线程同时扫描 22 个常见端口
3. Banner 抓取 — 连接成功后尝试读取服务指纹
4. 结果推送 — 通过 WebSocket 实时推送到浏览器

扫描的端口范围：
21(FTP) 22(SSH) 23(Telnet) 25(SMTP) 53(DNS)
80(HTTP) 110(POP3) 143(IMAP) 443(HTTPS) 445(SMB)
993(IMAPS) 995(POP3S) 1433(MSSQL) 1521(Oracle)
3306(MySQL) 3389(RDP) 5432(PostgreSQL) 5900(VNC)
6379(Redis) 8080(HTTP-Alt) 8443(HTTPS-Alt) 27017(MongoDB)
```

**教学要点：**
- `socket.connect_ex()` 返回 0 表示端口开放，非 0 表示关闭或不可达
- 多线程扫描用 `threading.Lock` 保证结果列表的线程安全
- 扫描完如果开放端口 > 5 个，自动生成 WARNING 级别告警

### 3.2 Web 漏洞扫描

**操作步骤：**
1. 在扫描中心选择"Web 漏洞扫描"
2. 输入目标 URL（如 `http://testphp.vulnweb.com`）
3. 点击"开始扫描"

**技术原理（三阶段）：**

```
阶段一：信息收集
├── 发送 GET 请求获取 HTTP 状态码
├── 检查 Server / X-Powered-By 头部（技术栈泄露）
└── 检查安全头部是否存在：
    ├── X-Frame-Options（防点击劫持）
    ├── X-Content-Type-Options（防 MIME 嗅探）
    ├── Content-Security-Policy（CSP 策略）
    └── Strict-Transport-Security（HSTS）

阶段二：目录扫描
├── /.env           ← 环境配置文件（常含密码）
├── /.git/HEAD      ← Git 仓库泄露
├── /backup.sql     ← 数据库备份
├── /config.php     ← 配置文件
├── /admin/         ← 后台管理入口
├── /phpmyadmin/    ← 数据库管理界面
├── /wp-admin/      ← WordPress 后台
├── /.htaccess      ← Apache 配置
└── /robots.txt     ← 爬虫规则

阶段三：XSS 检测
├── 注入 payload: <script>alert(1)</script>
├── 测试参数: ?q=, ?search=, ?query=
└── 检查响应中是否原样反射 payload
```

**严重程度分级：**
| 等级 | 含义 | 示例 |
|------|------|------|
| HIGH | 高危，需立即修复 | .env 文件可访问、缺少 CSP |
| MEDIUM | 中危，建议修复 | 缺少 X-Frame-Options |
| LOW | 低危，安全加固 | 缺少 X-Content-Type-Options |
| INFO | 信息收集 | Server 头部暴露版本 |

### 3.3 日志分析

**操作步骤：**
1. 在扫描中心选择"日志分析"
2. 输入日志文件路径（默认 `/var/log/auth.log`）
3. 点击"分析"

**技术原理：**
```
解析流程：
1. 逐行读取 auth.log
2. 正则匹配 SSH 失败登录：
   - 格式1: "Failed password for <user> from <ip>"
   - 格式2: "Failed password for invalid user <user> from <ip>"
3. 按 IP 和用户名分别统计失败次数
4. 暴力破解检测：
   - 同一 IP 失败 >= 5 次 → MEDIUM 告警
   - 同一 IP 失败 > 20 次 → HIGH 告警
5. 返回 Top 10 攻击 IP、Top 10 被暴破用户名
```

---

### 3.4 实时告警系统

**工作原理：**
```
扫描触发 → 生成告警 → 存入 SQLite → WebSocket 推送 → 浏览器实时显示

告警触发规则：
- 端口扫描：开放端口 > 5 个 → WARNING
- Web 扫描：存在 HIGH 级别发现 → CRITICAL
- 日志分析：单 IP 失败登录 > 20 次 → HIGH
```

## 四、⚡ 安全性教学重点

### 4.1 API Key 与凭证安全（核心考点）

#### ⚠️ 本项目存在的安全问题（教学演示用）

**问题 1：硬编码密钥**
```python
# app.py 第 27 行 — 危险写法！
app.secret_key = "autoops-security-dashboard-2026"

# 正确做法：使用环境变量或随机生成
import os
app.secret_key = os.environ.get('SECRET_KEY') or os.urandom(24)
```

**问题 2：明文密码存储**
```python
# app.py 第 110 行 — 危险写法！
if username == "admin" and password == "admin123":

# 正确做法：使用 werkzeug 的密码哈希
from werkzeug.security import check_password_hash
if username == "admin" and check_password_hash(stored_hash, password):
```

**问题 3：无 CSRF 保护**
```python
# POST /api/scan/port 等接口没有 CSRF token 验证
# 正确做法：使用 Flask-WTF 的 CSRFProtect
from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)
```

**问题 4：CORS 全开**
```python
# SocketIO 初始化时 CORS 设为 "*"
# 正确做法：限制为实际域名
socketio = SocketIO(app, cors_allowed_origins="http://localhost:5000")
```

**问题 5：debug=True 上线**
```python
# 生产环境必须关闭 debug
socketio.run(app, host='0.0.0.0', port=5000, debug=False)
```

### 4.2 安全编码清单

```
✅ 所有密码必须哈希存储（bcrypt / argon2 / werkzeug）
✅ Secret Key 从环境变量读取，绝不硬编码
✅ 敏感配置通过 .env 文件管理，加入 .gitignore
✅ API 接口必须验证输入参数（类型、长度、范围）
✅ 生产环境关闭 debug 模式
✅ 使用 CSRF 保护所有状态变更接口
✅ CORS 只允许可信域名
✅ 登录接口加速率限制（Flask-Limiter）
✅ 扫描目标必须做白名单校验（防止 SSRF）
```

### 4.3 防止 API Key 泄露的代码模式

```python
# ❌ 错误：硬编码在代码里
API_KEY = "sk-abc123secretkey"

# ✅ 正确：环境变量
import os
API_KEY = os.environ.get('API_KEY')
if not API_KEY:
    raise ValueError("请设置 API_KEY 环境变量")

# ✅ 正确：使用 .env 文件 + python-dotenv
from dotenv import load_dotenv
load_dotenv()  # 从 .env 文件加载
API_KEY = os.environ.get('API_KEY')

# .env 文件内容（不提交到 git）：
# API_KEY=sk-abc123secretkey
# SECRET_KEY=your-random-secret

# .gitignore 中必须包含：
# .env
# *.db
```

## 五、代码架构教学

### 5.1 引擎与接口分离

```
scanner_engine.py（纯逻辑，无 Flask）
├── PortScanner   — 端口扫描
├── WebScanner    — Web 漏洞扫描
├── LogAnalyzer   — 日志分析
└── IDSEngine     — 入侵检测规则引擎

app.py（Web 层，调用引擎）
├── 路由处理
├── 用户认证
├── WebSocket 事件
└── 数据库操作
```

> **教学意义：** 扫描引擎不依赖任何 Web 框架，可以独立测试、复用到 CLI 工具中。

### 5.2 异步扫描模式（Fire-and-Forget）

```python
@app.route('/api/scan/port', methods=['POST'])
@login_required
def api_port_scan():
    # 1. 立即通知前端"扫描已开始"
    socketio.emit('scan_progress', {'status': 'started', 'type': 'port'})

    # 2. 在后台线程中执行扫描
    def run_scan():
        results = scanner.scan(target)      # 耗时操作
        socketio.emit('scan_result', {...})  # 完成后推送结果

    thread = threading.Thread(target=run_scan, daemon=True)
    thread.start()

    # 3. 立即返回，不阻塞前端
    return jsonify({'status': 'started'})
```

> **教学意义：** Web 应用中处理耗时任务的标准模式，避免 HTTP 请求超时。

### 5.3 WebSocket 实时推送

```
服务端                              客户端
   │                                   │
   ├── emit('scan_progress') ────────→ │ 更新进度条
   │                                   │
   │    [后台线程执行扫描...]            │
   │                                   │
   ├── emit('scan_result') ──────────→ │ 显示扫描结果
   │                                   │
   ├── emit('new_alert') ────────────→ │ 弹出告警通知
```
